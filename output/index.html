    pgirl/genomic-intelligence: Output¶

    Introduction¶

    This document describes the output produced by the pipeline. Most of the plots are taken from the MultiQC report, which summarises results at the end of the pipeline.

    The directories listed below will be created in the results directory after the pipeline has finished. All paths are relative to the top-level results directory.

    Pipeline overview¶

    The pipeline is built using Nextflow and processes data using the following steps:

    • Nextclade - Pathogen classification and clade assignment
    • Nextstrain - Phylogenetic tree building
    • Annotations - Tip metadata and mutation matrix extraction
    • Figures - Annotated phylogenetic tree visualisations
    • MultiQC - Aggregate report
    • Pipeline information - Report metrics generated during the workflow execution

    Nextclade¶

    Output files
    • nextclade/results/
    • *.tsv: Nextclade classification results per sample.
    • *.json: Detailed JSON output with clade assignments and mutations.
    • *.aligned.fasta: Reference-aligned sequences.

    Nextclade assigns sequences to clades, calls mutations, and performs quality checks against a reference dataset.

    Nextstrain¶

    Output files
    • nextstrain_ebola/
    • results/<species>/all-outbreaks/tree.nwk: Phylogenetic tree in Newick format.
    • results/<species>/all-outbreaks/muts.json: Per-node mutation data.
    • results/<species>/all-outbreaks/branch_lengths.json: Branch length data.
    • auspice/*.json: Auspice JSON for interactive visualisation.

    The Nextstrain/augur pipeline builds a maximum-likelihood phylogenetic tree, infers ancestral states, and exports results for interactive visualisation in Auspice.

    Annotations¶

    Output files
    • nextstrain_ebola/annotations/
    • <species>_tip_metadata.tsv: Tip-level metadata (country, clade, QC, mutations).
    • <species>_mutation_matrix.tsv: Binary matrix of top 5 amino-acid mutations per protein.
    • <species>_mutation_legend.tsv: Legend mapping mutation columns to genes and frequencies.
    • <species>_node_metadata.tsv: Internal node metadata.

    Figures¶

    Output files
    • nextstrain_ebola/figures/
    • <species>_ggtreeExtra.png: Annotated rectangular phylogeny with branches colored by country and a binary heatmap of top amino-acid mutations.

    Tree figures are generated with ggtree and ggtreeExtra. Query tips are highlighted with red diamonds.

    MultiQC¶

    Output files
    • multiqc/
    • multiqc_report.html: a standalone HTML file that can be viewed in your web browser.
    • multiqc_data/: directory containing parsed statistics from the different tools used in the pipeline.
    • multiqc_plots/: directory containing static images from the report in various formats.

    MultiQC is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

    Results generated by MultiQC collate pipeline QC from supported tools e.g. FastQC. The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see http://multiqc.info.

    Pipeline information¶

    Output files
    • pipeline_info/
    • Reports generated by Nextflow: execution_report.html, execution_timeline.html, execution_trace.txt and pipeline_dag.mmd (raw Mermaid DAG).
    • pipeline_metro_map_*.html — auto-generated nf-metro metro-map diagram of the run's task graph, converted from pipeline_dag.mmd (skipped with a warning if nf-metro is unavailable).
    • Reports generated by the pipeline: pipeline_report.html, pipeline_report.txt and software_versions.yml. The pipeline_report* files will only be present if the --email / --email_on_fail parameter's are used when running the pipeline.
    • Reformatted samplesheet files used as input to the pipeline: samplesheet.valid.csv.
    • Parameters used by the pipeline run: params.json.

    Nextflow provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
